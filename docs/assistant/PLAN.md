# 主动助理实施计划

> 依赖关系：M0 可与 M1 并行；M3 依赖 M1 的 JSON 契约，但可用 `--mock` 先行；M2 依赖 M1 的状态机。

## 里程碑总览

| 里程碑 | 内容 | 验收 | 估时 |
|---|---|---|---|
| M0 环境与壳 | Tauri 脚手架、透明/置顶/不抢焦点、随机边缘滑入、托盘、自启、10 分钟缩回 | 假气泡能滑入、10 分钟后自动缩回、托盘常驻、打字不被打断 | 0.5–1 天 |
| M1 core 骨架 | `ton assistant tick/inbox/ack/act`、state.db、去重/静默/冷却、假数据 probe | 空轮 0 次模型调用；ack/snooze 正确；重启恢复 | 1.5–2 天 |
| M2 真实数据源 | spc `wechat_recent`、禅道 MCP、承诺记忆、triage、自动闭环 | 48 小时 dry-run 后人工对照，误报可接受 | 2 天 |
| M3 大窗接入 | 30 分钟定时 spawn tick、卡片/按钮、批次合并、多屏、托盘角标 | 真实事项驱动气泡；按钮生效；重启恢复待办 | 2–3 天 |
| M4 批复与动作 | 马上做分派、草稿、撤销、结果回显、TUI `/inbox` | 草稿可复制；禅道能拉起终端；状态三方一致 | 1.5–2 天 |
| M5 面板与降噪 | 待处理/静默/历史/决策日志、暂停/勿扰、全屏/锁屏/空闲、数据源健康 | 能回答「这轮为什么没报」；暂停立即生效 | 1.5 天 |
| M6 影子运行与扩展 | 48h 只看不弹 → 开推送；邮件、评审、背景卡、周报、运维 | 连续一周误报率稳定 | 持续 |

P0–P5 合计约 **9–12 个工作日**。M6 不是一次性交付，是上线后的迭代节奏。

## M0 环境与壳

范围：

- 装 `librsvg2-dev`；跑通 Tauri v2 依赖检查
- `packages/desktop` 脚手架，`src-tauri` + `src`
- 窗口：透明、无边框、置顶、跳过任务栏、不进任务切换器
- 测试模式下的「假气泡」：随机边、随机位置、滑入、10 分钟缩回、悬停暂停
- 托盘常驻 + 菜单骨架（打开收件箱 / 现在探测 / 暂停 / 退出）
- 单实例、开机自启
- 合成器检测与兜底路径验证

验收：

1. 连续触发 20 次假气泡，每次从不同边/位置滑入，不闪黑底。
2. 10 分钟无操作自动缩回；鼠标悬停期间计时暂停；移开后重新计时。
3. 气泡出现时，在其他窗口里连续打字不丢焦点、不丢按键。
4. 关闭主窗口后进程仍在，托盘可再次唤起。
5. 重启系统后自动启动，且只有一个实例。

已知前置：本机 `_NET_WM_CM_S0` 当前不存在（xfwm4 配了 `use_compositing=true` 但合成未真正生效）。M0 必须二选一：拉起合成，或走 XShape 圆角/不透明兜底。见 DESKTOP.md 第 9 节。

## M1 core 骨架

范围：

- `packages/coding-agent/src/assistant/`：`paths / db / state / policy / probe / triage / cli`
- SQLite（`node:sqlite`，WAL）：`items / runs / cursors / events`
- 指纹与去重、状态机、静默/冷却/每日上限/静默时段
- 假 probe（读取 fixtures JSON），先把「探测 → 过滤 → 决策 → 落库」跑通
- `ton assistant tick --json --mock <file>` / `inbox` / `ack` / `act` / `status` / `pause` / `resume`

验收：

1. 无候选时 tick 不调用模型，`model_calls=0`。
2. 同一事项连续 5 轮只报 1 次（24h 冷却）。
3. `ack <id> --state muted --for 3d` 后，3 天内该指纹不再出现。
4. `ack <id> --state later` 到期后重新进入待报。
5. 杀进程再启动，未处理事项、游标、暂停状态都还在。
6. 单元测试覆盖上述 5 条。

## M2 真实数据源

范围：

- spc 侧新增只读工具 `wechat_recent`（规格见 PROBES.md）
- 禅道 MCP 接进 `~/.ton/agent/mcp.json`（本地文件，不进仓库）
- spc `list_memories` 中的承诺/待办到期检查
- triage：`completeSimple` + 严格 JSON，失败降级
- 自动闭环：微信 `last_me_at` 前进、禅道状态变化、memory closed
- 默认 `dryRun=true`，只记录不推送

验收：

1. `ton assistant tick --dry-run --json` 连续跑 48 小时，产出可读的决策日志。
2. 人工对照：该报的漏了几条、不该报的多了几条，形成清单再调 prompt/阈值。
3. spc 不可用、禅道 token 失效、模型报错三种情况都不崩，退出码为 2 并在 `runs.error` 留痕。
4. 微信里你回复后，下一轮该事项自动 `done`。

## M3 大窗接入

范围：

- Rust 定时器 30 分钟（± 0–5 分钟抖动）spawn `ton assistant tick --json`，120s 超时
- 解析 stdout，按 `batch` 渲染卡片（最多 3 张）
- 按钮：马上做 / 知道了 / 别再说了 / ⋯
- 10 分钟缩回、悬停暂停、新批次合并并重置计时
- 多屏：鼠标所在屏；workarea 扣掉面板；HiDPI 物理像素
- 托盘角标：待处理条数

验收：

1. 真实 tick 驱动气泡，端到端无手工步骤。
2. 点「知道了」→ 卡片立即消失，DB 状态为 `later`，2 小时内不再出现。
3. 点「别再说了」→ 3 天内不再出现。
4. 拔掉外接屏/换主屏后气泡仍完整可见（不越界、不被面板遮住）。
5. 关闭桌面端期间产生的待办，启动后进入收件箱。

## M4 批复与动作

范围：

- 「马上做」分派：
  - 微信未回 → 卡内生成草稿，复制/重写，不自动发送
  - 禅道 bug → 拉起终端，带 bug 上下文进入 ton TUI
  - 承诺 → 起草 / 建 todo / 改提醒时间
- 5 秒内可撤销
- 结果回显（成功/失败/需要人工）
- TUI 侧 `/inbox` 与自然语言批复（「第 2 条不用管了」）走同一命令

验收：

1. 三类事项的「马上做」都能给出可执行结果。
2. 撤销后状态与通知都回滚。
3. TUI 和桌面端看到同一份收件箱，操作互相同步。

## M5 面板与降噪

范围：

- 面板：待处理 / 已静默 / 历史 / 决策日志（本轮看到什么、为什么报/没报）
- 暂停 1 小时 / 今天 / 明天；勿扰时段可视化
- 全屏、锁屏、空闲自动降噪
- 数据源健康：spc 断连、禅道 token 失效、模型额度不足要主动报
- 统计：每周报了多少、静音了哪些类型，给降级建议

验收：

1. 任一事项能追溯「哪一轮、哪个 probe、哪条规则」。
2. 暂停后下一轮 tick 不产生气泡。
3. 数据源故障在 1 小时内出现在托盘状态里。

## M6 影子运行与扩展

范围：

- 先 48 小时只看不弹，校准阈值，再打开推送
- 按「probe 适配器 + 判定规则」增场景：邮件、评审/等待项、背景卡、周报、运维告警
- 飞书轮询作为离开电脑时的可选通道（不放进首版）

验收：连续一周，每天主动打扰 ≤ 8 次，用户静音率 < 30%。

## 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 合成器缺失 | 透明大窗渲染成黑底 | M0 先拉起合成；不行走 XShape 圆角兜底 |
| X11 抢焦点 | 打字被打断 | GTK `accept_focus(false)` + 不调用 `present`；实测 |
| 多屏 workarea | 盖住面板、跑错屏 | GDK monitor workarea + 物理像素换算 |
| WebKitGTK 动画掉帧 | 滑入卡顿 | 只动 transform/opacity；窗口位移步数可控 |
| spc 游标不准 | 漏消息/重复报 | 消息 ts + 文件 mtime 双校验 |
| 桌面端没开 | 完全不探测 | 自启 + 托盘健康提示 + 手动「现在探测」 |
| triage 解析失败 | 漏报 | 严格 JSON + 校验失败降级为原始候选列表 |
| 每日上限误伤 | 急事晚报 | P0 绕过上限与静默时段 |
| 模型成本 | 频繁调用 | 无候选 0 调用；候选才调 flash；单轮上限 1 次 |

## 排期建议

单人全职：M0+M1 并行（第 1–3 天）→ M2（第 4–5 天）→ M3（第 6–8 天）→ M4（第 9–10 天）→ M5（第 11–12 天）→ M6 持续。

两人并行（核心 + 桌面）：M1 与 M0/M3 骨架同起，M2 与 M3 收尾并行，M4 汇合。
